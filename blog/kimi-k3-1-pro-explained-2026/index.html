Kimi K3.1 Pro explained: the 2.8T open-weight AI model with 1M context, and what it means for small dev teams (2026)

Quick answer

Kimi K3.1 Pro is Moonshot AI's newest flagship model: a 2.8-trillion-parameter mixture-of-experts system with a 1,048,576-token context window, built for software agents that plan, call tools, and work through long tasks on their own. Moonshot launched it on October 23, 2026, then published the full weights on Hugging Face on November 4, 2026 — a 1.56 TB download anyone can inspect. The managed API starts at $2 per million input tokens and $10 per million output tokens. The catch is in the license: it is open-weight, not open source, and companies earning over $20 million a year need a separate agreement before selling it as a service. For most small dev teams, the API — not self-hosting — is the realistic way in.

What Kimi K3.1 Pro actually is

Kimi K3.1 Pro comes from Moonshot AI, the Chinese AI company founded by Yang Zhilin, best known for the Kimi chatbot and its long-context models. The model launched on October 23, 2026, and the full weights followed on Hugging Face on November 4, 2026, in the repository moonshotai/Kimi-K3.1-Pro — 96 safetensors files totalling about 1.56 TB. That is the headline: a frontier-class model whose weights are public, not locked behind one company's API.

It is natively multimodal, taking text and image input, and it is designed first and foremost as an agent model — software that plans multi-step work, calls tools, reads the results, and keeps going, rather than just answering a single question. That is the same shift our guide to AI agents explained describes: the useful unit is no longer one prompt and one answer, but a model that can run a task to completion. Kimi K3.1 Pro is Moonshot's entry in that race, aimed squarely at coding and software engineering work.

You can meet it in four places: Kimi.ai (the chat product), Kimi Work and Kimi Code (its work and coding products), and the Kimi API for developers. Microsoft added it to Azure AI Foundry on November 6, 2026, which matters for teams that already run on Azure and want a second frontier model without a new vendor relationship. Prices and claims in this article were checked on November 8, 2026 — confirm them on Moonshot's own pages before budgeting, because launch-week pricing moves fast.

The numbers, explained in plain English

The spec sheet reads like a dare: 2.8 trillion total parameters, 104 billion activated per token, 896 experts, 16 selected per token, a 1,048,576-token context, and MXFP4 weights. Here is what each number actually means for you.

2.8 trillion parameters, 104 billion active. Kimi K3.1 Pro is a mixture-of-experts (MoE) model. Think of it as a company with 896 specialist teams. For any given word it generates, only 16 teams are consulted — about 104 billion parameters' worth of work — while the rest sit idle. The model is enormous in total, but the cost of each answer depends only on the slice that wakes up. That is why a 2.8T model can be priced anywhere near a much smaller one: you pay for the experts used, not the whole company.

1,048,576-token context. A token is roughly three-quarters of a word, so 1M tokens is around 750,000 words — roughly ten average novels, or a very large codebase. In practice, that means you can hand the model your whole repository, a stack of documentation, and a long conversation history in a single session and it can still find the relevant detail. The honest caveat: long context is only useful if the model stays accurate at the far end of it, and that is exactly what long-context benchmarks exist to test. Big context is a capability, not a guarantee.

MXFP4 weights. This is the compression format the weights are stored in — 4-bit floating point. It is one reason the download is 1.56 TB instead of several times that, and it is also why running the model needs specialised hardware and software that understand the format. The headline number, 1.56 TB, is the one to remember: it sets the floor for everything in the self-hosting section below.

Open weights is not open source — read the license

The most misunderstood word in this launch is "open". Kimi K3.1 Pro is open-weight: the trained model files are public and downloadable. It is not open source under a standard license like Apache 2.0 or MIT. It ships under a custom Kimi K3.1-Pro License, and the difference has real consequences.

The headline condition: companies with over $20 million in revenue in a 12-month period need a separate agreement with Moonshot before selling the model as a service. Internal use is exempt — a big company can run it for its own engineers without that agreement — but a smaller company that wants to build a product on top of Kimi and charge customers for it can hit the threshold fast. If your plan is to wrap the model in a paid service, get the license read by someone who reads licenses for a living before you build on it.

Two more facts belong here. First, open weights do not include the training data or the full training recipe, so "open" does not mean you can reproduce the model or audit exactly what it learned. Second, Moonshot says cyber-related data was removed from the model's training — a safety claim from the vendor, not an independently verified fact. None of this makes the release a bad thing: downloadable frontier weights are genuinely rare and useful for research, evaluation, and fine-tuning. It just means the word "open" is doing more work in the headlines than it does in the license.

For a sense of scale: a coding session that sends 100,000 input tokens and receives 20,000 output tokens costs about $0.40 on the standard Kimi API — cheap per session, and the bill that matters is the monthly one across a whole team. The $1 minimum top-up makes trying it nearly free, which is the right way to start: pay a dollar, run your real tasks, and measure the bill against the work it actually did.

Two cost traps to watch. First, the 1M context is a meter that runs: long sessions with a huge codebase in context burn input tokens on every turn, even when the model only needs a small part of it. Second, agentic work is output-heavy — a model that plans, writes code, tests, and rewrites can generate far more output tokens than a chatbot ever would, and output tokens cost five times input tokens. If you are comparing it with another frontier model, compare the price of a finished task, not the price of a million tokens. Benchmarks: what they do — and don't — prove

All benchmarks below are vendor-reported — Moonshot's own numbers, not independent verification. That label matters, because benchmark scores are the easiest numbers in AI to inflate by accident or design. Treat them as a signal, not a verdict.

BenchCAD (with tools)92.7——

Terminal-Bench 4.0 tests what the model is built for: real software tasks in a terminal — writing code, running commands, fixing errors, and finishing multi-step jobs. Kimi's 65.7% sits a fraction behind Claude Opus 5.5 at 66.4% and well ahead of GPT-6 Astra at 58.2%, according to Moonshot. BenchCAD, a computer-aided-design benchmark run with tools, scores 92.7 — but Moonshot did not publish comparable rival numbers for it, so it tells you the model can use CAD tools, not that it beats anyone at them.

What these numbers do prove: Kimi K3.1 Pro is in the frontier conversation for agentic coding, not a distant second. What they do not prove: that it will do your team's work well. Benchmarks use fixed tasks and clean environments; your work has messy repositories, private APIs, and vague requirements. The only benchmark that counts is yours: give it five real tasks from your backlog, score the results honestly, and compare against whatever model you use today. Can a small dev team actually run it?

There are two different questions hiding in that headline, and they have opposite answers. Can a small team use Kimi K3.1 Pro? Yes, easily, through the API. Can a small team run the weights themselves? Almost certainly not — and the math shows why.

The weights are a 1.56 TB download. To run them, you need well over 1.5 TB of fast memory — GPU memory, not a hard drive — which means a multi-GPU server, not a laptop or a single desktop card. A single high-end consumer GPU holds 24 GB; you would need dozens of them, wired together with fast interconnects, plus the software to split a 2.8T mixture-of-experts model across them. The electricity, cooling, and engineering time alone would dwarf the API bill for any small team. Open weights do not mean runnable on your PC.

That is not a flaw in the release. The downloadable weights are valuable for researchers, for companies that need to evaluate the model privately, and for teams that want to fine-tune it — all jobs for organisations with serious GPU infrastructure. For a team of five or ten developers, the sensible path is the API or Foundry: you get the same model, you pay per token, and you keep zero servers. If you do want to run models locally, start with models built for it — our guide to running AI models on your own PC covers Llama and Nemotron on ordinary hardware, which is the right scale for a desk, not a data centre.

The middle path worth knowing about: hosted fine-tuning and private deployments through a cloud provider. You get the weights running on rented GPUs, with the provider handling the hardware. It is still a serious monthly bill, and it only makes sense once your API usage is large enough that renting beats paying per token — a calculation for a team spending thousands a month on inference, not tens.

How to try Kimi K3.1 Pro this week

Start with the free and cheap routes, in this order, and measure before you commit.

1. Chat with it on Kimi.ai. The fastest test: open Kimi.ai, upload a real document or image from your work, and ask it to do a real task — summarise a long spec, or plan a small feature from your codebase description. You are testing the 1M context and the agent behaviour, not the chat polish.

2. Try the coding products. Kimi Code is the coding surface; give it a small, well-defined task from your backlog — a bug fix or a test-writing job — and review the diff the way you would review a junior developer's pull request. Score it on whether the code runs, not whether it looks confident.

3. Top up $1 on the Kimi API. The minimum top-up is $1, which buys a meaningful amount of testing at $2 per million input tokens. Point one of your existing tools or scripts at the API, run the same five tasks you would benchmark any model on, and compare the finished work — and the bill — against your current model.

4. Check Microsoft Foundry if you are on Azure. Added on November 6, 2026, at $2.30 input and $11.50 output per million tokens, with cached input at $0.23. For Azure teams the advantage is not price — the Kimi API is slightly cheaper — but billing, compliance, and staying inside infrastructure you already run.

If the test week goes well, the next decision is not technical but commercial: confirm the license fits your use, especially the $20 million revenue condition if you plan to sell a service built on it, and set a monthly spend cap before the team starts using it in earnest. A model this capable is easy to adopt; the discipline is in measuring what it actually saves you.

Conclusion

Kimi K3.1 Pro is a genuinely significant release: a frontier-class agent model, with a million-token context and benchmark scores near the best in the world, whose weights anyone can download. But the two things that will decide whether it matters to your team are not on the spec sheet — the custom license, which is not open source and carries a $20 million revenue condition for selling it as a service, and the 1.56 TB of weights, which put self-hosting out of reach for small teams. Use the API, test it on real work, and let your own tasks — not the vendor's benchmarks — make the decision.
